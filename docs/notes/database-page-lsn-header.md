# 页面、页面头和 LSN

## 对页面的当前理解

“一个数据文件被划分成很多页面，每个页面保存数据”是正确的，但页面里通常不只有用户数据，还会有描述页面状态的元数据。

RUCBase 的页面大小是：

```cpp
PAGE_SIZE = 4096;  // 4 KB
```

可以把一页粗略看成：

```text
固定大小的字节区域 = 页面元数据 + 实际数据
```

## 什么是页面头

页面头（page header）是页面开头的一小段元数据，用来描述或管理这个页面，而不是用户表中的普通记录。

它可能记录：

- 页面所属或版本相关信息；
- 页面中的记录数量；
- 空闲页链表中的下一个页面；
- 日志恢复所需的 LSN。

页面头和“文件头页面”不是同一个概念：

- **页面头**：每个页面内部开头的一段元数据；
- **文件头页面**：文件中的某一个专门页面（RUCBase 记录文件中通常是第 0 页），记录整个文件的元信息。

## RUCBase 中的两层页面头

记录数据页的布局是：

```text
Page 公共元数据（LSN） | RmPageHdr | bitmap | 定长记录槽
```

其中：

- `Page` 的公共区域目前放 LSN；
- `RmPageHdr` 是记录模块自己的页面头，保存 `next_free_page_no` 和 `num_records`；
- `bitmap` 标记哪些记录槽已经被占用；
- 后面才是实际记录内容。

因此 `RmPageHdr` 是“记录页头”，而 LSN 属于更通用的页面元数据。

## 什么是 LSN

LSN 是 **Log Sequence Number**，即“日志序列号”。它是日志记录的编号，用于表示日志记录的先后顺序。

当数据库修改页面时，通常先产生描述这次修改的日志，再把页面写回磁盘。页面中保存一个 LSN，可以表示：

> 这个页面已经应用到哪一条日志为止。

恢复系统可以比较页面 LSN 和日志 LSN，判断某条修改是否已经写入页面，以及崩溃恢复时哪些日志需要重做或跳过。

Lab1 主要需要知道它占据页面前 4 个字节；详细的日志恢复逻辑属于后续内容。

## 当前页面布局中的具体位置

```cpp
static constexpr size_t OFFSET_LSN = 0;
static constexpr size_t OFFSET_PAGE_HDR = 4;
```

表示：

```text
data_[0..3]     保存页面 LSN（当前 lsn_t 为 4 字节）
data_[4..]      从 OFFSET_PAGE_HDR 开始放其他页面结构
```

## 一个具体例子

假设某记录页中：

```text
LSN = 27
num_records = 3
```

内存布局仍然类似：

```text
字节 0~3       字节 4~...
┌───────────┬─────────────────────────────┐
│ LSN = 27  │ RmPageHdr、bitmap、记录数据 │
└───────────┴─────────────────────────────┘
```

LSN 不是用户表中的一列，也不是记录本身；它是数据库内部为了日志和恢复而保存的页面状态。

## 一个重要区分

```text
文件 → 页面 → 页面头 + 页面数据
```

对于记录文件，还可以进一步展开：

```text
记录文件
├── 第 0 页：RmFileHdr（整个文件的元信息）
├── 第 1 页：LSN + RmPageHdr + bitmap + 记录槽
├── 第 2 页：LSN + RmPageHdr + bitmap + 记录槽
└── ...
```
